# DPN PhaseGate AURORA v0.9 — Native Interface Redesign

[Main repository](../../README.md) · [Download Windows EXE workflow](https://github.com/DevelopPioneerNavigate/DPN-PhaseGate/actions/workflows/native-windows-exe.yml) · [PG-01 engineering atlas](../VISUAL-ATLAS.md)

> **AURORA is a software-design upgrade, not a physical portal breakthrough.** Every energetic orbital animation is **illustrative artwork** and every Command Center/Signal Analytics waveform remains **SYNTHETIC**. Real USB RAW data only appear in Hardware Lab after deliberate operator connection.

## Why AURORA exists

Previous versions presented small cards with relatively little hierarchy and simple single-outline rings. AURORA develops PhaseGate into an expansive, readable, distinctive **native Qt engineering command center**. No Electron, embedded web browser, remotely loaded fonts, paid APIs, or misleading physics simulation.

## Information architecture

```
DPN / PHASEGATE    •    AURORA MISSION CONTROL
│
├── [01] Command Center          Cinematic field visualization + honest research status
├── [02] Station Matrix          Synthetic concept view of station A/B
├── [03] Hardware Lab            Operator connected physical USB RAW counts only
├── [04] Calibration & Evidence  Unreviewed gram estimates + witness file hash
├── [05] Signal Analytics        Explicitly simulated diagnostic traces
├── [06] Research Vault          Real bibliography registry, read-only
├── [07] Experiment Ledger       Actual real-run registry; no created false results
├── [08] System Diagnostics      Qt runtime, bundle and local integrity checks
└── [09] Preferences             Reduced animation and synthetic update cadence
```

The rendering uses Qt Widgets/QPainter and the existing desktop model. All previous hardware drivers, raw bench recording, calibration and witness provenance logic are retained. No underlying experimental file semantics change.

## Interaction

- **Ctrl+K** — Open type-to-filter destination palette. Select a result and press Enter.
- **Ctrl+1 through Ctrl+9** — Navigate to the respective screen, without activating instruments.
- **F11** — Toggle fullscreen immersive workstation view.
- **Mission hero buttons** — Open Hardware Lab and Calibration & Evidence Lab.
- **Motion option** — Existing Preferences control pauses both station renderers and the new AURORA field effect.
- **No hardware auto-connect** — Switching pages and playing visual effects never opens COM ports, sends serial commands or launches cameras.

## Native art guidance

- Electric cyan indicates instrumentation and computer data, violet represents research/experimental design, and amber indicates limitations and required review.
- The diagrammatic field is marked `CONCEPT RENDER / NO PORTAL`; there is no physical wormhole or matter-moving mechanism.
- Numbers represent either real research registry counts or explicitly labeled synthetic/candidate diagnostics; they are never merged into one "verified research" indicator.
- Honor screen-reader/motion accessibility as the native Qt design expands; manual motion pause already exists.

## Quality gates and artifacts

The Windows GitHub Actions pipeline runs repository research validation and Python unit tests, verifies all nine native Qt pages render/navigate, saves actual desktop UI captures for Command Center, Hardware Lab and Calibration & Evidence Lab, builds a single-file `DPN-PhaseGate.exe`, and executes that EXE's self-test before publishing it.

The v0.9 application download is named `DPN-PhaseGate-Native-Windows-v0.9`. The screenshot archive is named `DPN-PhaseGate-Native-Preview-v0.9`. Download either from the green [native Windows workflow](https://github.com/DevelopPioneerNavigate/DPN-PhaseGate/actions/workflows/native-windows-exe.yml) artifact list. Windows build/signing constraints remain the same; EXE builds are unsigned.

### Scientific boundary

A beautiful instrument interface is not a breakthrough. v0.9 adds no proof of macroscopic teleportation, camera evidence, physical calibration certification or device clock synchronization. These require independently verified hardware experiments and safe protocols.
